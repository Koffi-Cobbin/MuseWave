# Playlist Sharing — Frontend Integration Summary

## Overview

Playlists now have Google Drive-style access control. A playlist owner can:
- Share with specific users (by username or email) with **view** or **edit** permission
- Generate a **shareable link** that anyone can use (optionally with edit access)
- Make a playlist **public** so it appears on their profile for anyone to browse

Every playlist response now includes a `my_permission` field that tells the client exactly what the current user can do.

---

## Permission Levels

| Value | What the user can do |
|---|---|
| `"owner"` | Everything — manage shares, generate links, edit, delete |
| `"edit"` | Add/remove/reorder tracks, update metadata |
| `"view"` | Read-only — view playlist and its tracks |
| `null` | No access (playlist is private and not shared with them) |

---

## Updated Playlist Response Shape

Every playlist endpoint now returns these additional fields:

```json
{
  "id": "uuid",
  "user_id": "uuid",
  "name": "My Playlist",
  "description": "...",
  "cover_url": null,
  "public": false,
  "link_permission": "view",
  "my_permission": "owner",
  "share_token": "uuid-or-null",
  "shares_count": 2,
  "tracks_count": 5,
  "track_ids": ["uuid", "uuid"],
  "created_at": "...",
  "updated_at": "..."
}
```

**Field visibility rules:**
- `share_token` — only non-null when the caller is the **owner** and a link has been generated
- `shares_count` / `shares` list — only visible to the **owner**
- `my_permission` — always present; use this to drive UI state (show/hide edit controls)

The detail endpoint (`GET /api/playlists/<id>`) returns the same shape but with a full `tracks` array instead of `track_ids`, and a `shares` array (owner only):

```json
{
  "shares": [
    {
      "id": "share-uuid",
      "playlist_id": "uuid",
      "shared_by_username": "alice",
      "shared_with_username": "bob",
      "shared_with_email": "bob@test.com",
      "shared_with_avatar": "https://...",
      "permission": "edit",
      "created_at": "..."
    }
  ]
}
```

## Endpoints

### 1. My Playlists
```
GET /api/playlists
Authorization: Bearer <token>
```
Returns all playlists the authenticated user **owns**. Each has `my_permission: "owner"`.

---

### 2. Get Playlist (access-controlled)
```
GET /api/playlists/<id>
Authorization: Bearer <token>        ← optional
```
Access is granted if the user is the owner, has a direct share, or the playlist is public.
To access via a link token, append it as a query parameter:
```
GET /api/playlists/<id>?token=<share_token>
```

---

### 3. Create Playlist
```
POST /api/playlists
Authorization: Bearer <token>
Content-Type: application/json

{
  "name": "Road Trip Mix",
  "description": "Optional",
  "public": false
}
```

---

### 4. Update Playlist
```
PATCH /api/playlists/<id>
Authorization: Bearer <token>
Content-Type: application/json

{
  "name": "New Name",
  "public": true
}
```
Requires **owner** or **edit** permission. Use `"public": true` to make it show on the user's profile.

---

### 5. Delete Playlist
```
DELETE /api/playlists/<id>
Authorization: Bearer <token>
```
Owner only.

---

### 6. Add / Remove / Reorder Tracks
```
POST /api/playlists/<id>/add-track
Content-Type: application/json
{ "track_id": "uuid" }

POST /api/playlists/<id>/remove-track
Content-Type: application/json
{ "track_id": "uuid" }

POST /api/playlists/<id>/reorder
Content-Type: application/json
[{"id": "playlist-track-uuid", "order": 0}, {"id": "playlist-track-uuid", "order": 1}]
```
All require **owner** or **edit** permission.

---

## Sharing — Direct User Grant (owner only)

### Share with a user
```
POST /api/playlists/<id>/shares
Authorization: Bearer <owner-token>
Content-Type: application/json

{
  "username": "bob",
  "permission": "view"
}
```
Use `"username"` OR `"email"` to identify the recipient — both are accepted, only one is required.
Permitted values for `permission`: `"view"`, `"edit"`.
If the user is already shared, this **updates** their permission instead of creating a duplicate.

**Response:**
```json
{
  "id": "share-uuid",
  "playlist_id": "uuid",
  "shared_by_username": "alice",
  "shared_with_username": "bob",
  "shared_with_email": "bob@test.com",
  "shared_with_avatar": "https://...",
  "permission": "view",
  "created_at": "..."
}
```

---

### List all shares
```
GET /api/playlists/<id>/shares
Authorization: Bearer <owner-token>
```
Returns an array of share objects (same shape as above).

---

### Change a user's permission
```
PATCH /api/playlists/<id>/shares/<share_id>
Authorization: Bearer <owner-token>
Content-Type: application/json

{ "permission": "edit" }
```

---

### Revoke a user's access
```
DELETE /api/playlists/<id>/shares/<share_id>
Authorization: Bearer <owner-token>
```

---

## Sharing — Public Link (owner only)

### Generate a shareable link
```
POST /api/playlists/<id>/link
Authorization: Bearer <owner-token>
Content-Type: application/json

{ "permission": "view" }
```
`permission` defaults to `"view"` if omitted. Calling this again **regenerates** the token, invalidating the old link.

**Response:**
```json
{
  "share_token": "20761cdb-c596-4666-a619-c9d501c5599d",
  "link_permission": "view"
}
```

The shareable URL to present to the user:
```
GET /api/playlists/link/<share_token>
```
No authentication is required to use this URL.

---

### Change link permission (without regenerating the token)
```
PATCH /api/playlists/<id>/link
Authorization: Bearer <owner-token>
Content-Type: application/json

{ "permission": "edit" }
```

---

### Revoke the link
```
DELETE /api/playlists/<id>/link
Authorization: Bearer <owner-token>
```
The old token becomes **immediately invalid** — any client using it will receive a `404`.

---

## Access via Link (no auth required)

```
GET /api/playlists/link/<share_token>
```
Returns the full playlist detail response. `my_permission` reflects the link's permission level (`"view"` or `"edit"`).
If the token has been revoked or never existed, returns `404 {"error": "Invalid or expired share link."}`.

---

## Playlists Shared With Me

```
GET /api/playlists/shared-with-me
Authorization: Bearer <token>
```
Returns a list of playlists that were **directly shared** with the authenticated user.
Each item includes `my_permission` showing their granted access level (`"view"` or `"edit"`).

---

## Public Playlists on a User's Profile

```
GET /api/users/<user_id>/playlists
```
No authentication required. Returns only playlists where `public: true`.
Use this to populate the playlists tab on a user's profile page.
Each item has `my_permission: "view"`.

---

## Error Responses

| Scenario | Status | Body |
|---|---|---|
| Not authenticated and playlist is private | `401` | `{"error": "Authentication required."}` |
| Authenticated but no access | `403` | `{"error": "You do not have access to this playlist."}` |
| Edit action with view-only permission | `403` | `{"error": "You do not have edit access to this playlist."}` |
| Delete attempted by non-owner | `403` | `{"error": "Only the playlist owner can delete it."}` |
| Share management by non-owner | `403` | `{"error": "Only the playlist owner can manage shares."}` |
| Username/email not found when sharing | `404` | `{"error": "No user found with username 'bob'."}` |
| Sharing with yourself | `400` | `{"error": "You cannot share a playlist with yourself."}` |
| Invalid link token | `404` | `{"error": "Invalid or expired share link."}` |

---

## UI Recommendations

| Scenario | Recommended behaviour |
|---|---|
| `my_permission === "owner"` | Show share button, manage access panel, delete button |
| `my_permission === "edit"` | Show add/remove track controls; hide share management |
| `my_permission === "view"` | Read-only — hide all edit controls |
| `share_token` is non-null | Show "Copy link" button using `GET /api/playlists/link/<share_token>` |
| `share_token` is null | Show "Generate link" button that calls `POST /api/playlists/<id>/link` |
| Sharing dialog | Accept username or email input; show dropdown for `view`/`edit`; POST to `/shares` to add; PATCH to change permission; DELETE to revoke |
| Shared-with-me tab | Call `GET /api/playlists/shared-with-me` and display alongside own playlists |
| Profile playlists tab | Call `GET /api/users/<id>/playlists` — no auth needed |
